# 施工影像轨迹与候选事件 v1

日期：2026-11-10。此契约只描述在现有检测证据上增加的可回溯轨迹和候选区域事件，不改变 `detections.json`、原视频或原始检测框。

## 业务范围

已完成视频检测后，使用项目环境中的 Ultralytics ByteTrack 适配器，对人员和设备类检测生成本次影像内的 `track_id`。用户可在当前检测画面上编辑一个像素候选区域，生成进入、持续停留和离开事件。事件均为算法候选，初始 `pending`，不代表真实人员身份、物理距离、法规违规或生产告警。

## 输出文件

- `tracks.json`：轨迹后端、实际版本、采样间隔、每个保存画面的 `track_id`、类别、bbox、来源检测索引和轨迹叠加图。
- `zones.json`：当前候选区域名称、原始检测画面像素坐标、停留阈值和创建时间。当前 UI 提供矩形，文件格式保留多边形。
- `events.json`：候选事件类型、对象 ID、起止时间、持续时长、关键帧证据、人工状态和限制说明。

轨迹 ID 只在本次 review 目录内有效；不能作为员工身份、跨摄像头身份或去重后的真实人数证明。检测器漏检时轨迹可能断裂，系统记录实际保存结果，不补造框。

## 实现边界

ByteTrack 使用官方开源算法；当前运行入口是已安装 Ultralytics 版本中的 `ultralytics.trackers.byte_tracker.BYTETracker`，运行依赖 `lap` 已固定。检测和跟踪分离，跟踪失败不得静默替换或修改 PPE 结果。原视频、输入帧、检测 JSON SHA 不变。

区域坐标基于保存画面的像素尺寸，不转换为米；无相机标定时不生成“2 米”或真实距离结论。事件关键帧用于后续 AI 巡查总结优先选取，AI 仍只能归纳可见画面，问题全部交人工确认。

## 验收标准

1. 固定结构施工视频 8–12 秒采样中，真实检测框可生成至少 3 个稳定对象 ID；输出包含实际帧号和时间。
2. 轨迹叠加图显示对象 ID 和历史路径；原始检测 JSON、视频和输入画面 SHA 不变。
3. 一个有效矩形候选区域可生成进入/停留/离开事件；每条事件包含关键帧、起止时间和 `pending` 状态。
4. 重新生成区域只更新派生 `zones/events/tracks`，不覆盖检测原件；完整 ZIP 递归包含这些证据。
5. 生成候选事件后，AI 总结优先使用事件关键帧；人工保存和导出不新增 API 请求。
6. 跟踪依赖缺失时页面明确提示，检测仍可查看和导出；不得伪造轨迹或事件。
