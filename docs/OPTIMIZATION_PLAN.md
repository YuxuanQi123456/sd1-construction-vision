# 施工安全视觉演示优化方案

更新：2026-11-08；依据代码基线 `e202213` 和 V13 记录。本文件是共同开发建议，未实施以下优化、训练或新增业务。当前任务与状态分别由 [项目任务书](PROJECT_TASKBOOK.md)、[项目进度](PROJECT_PROGRESS.md) 管理（两文件由本轮主集成任务新增）；[PROGRESS](PROGRESS.md) 保留详细历史。

## 目标与已验证起点

下一步优先把领导能独立操作的固定施工安全演示做稳：选素材、真实检测、按需头部复核、查看依据、导出可读报告。允许针对演示素材调参或过拟合，优先复用现有开源应用与权重；不以扩大模型规模或增加 API 调用作为默认解法。样例适配结果必须标明用途，不称为独立现场泛化成绩。

[V13 总验收](validation/V13_SAFETY_DEMO.json) 已记录真实 CPU YOLO、浏览器流程及一次真实 GPT 头部复核；[模型选择](validation/V13_MODEL_SELECTION.json) 有 36 次固定帧推理对照。默认 `site-action` 使用 SiteWatch、standard、阈值 0.40；近景备用使用 Constructelligence v0.3。现有三视频、三照片及其推荐配置见 [素材清单](../sitewatch/demo-media.json)。原件、原尺寸 PNG、真实框和分数、采样时间及第二意见已有导出链路，见 [演示顺序](PPE_DEMO.md)。

V13 的一个三帧流程检测耗时约 4.99 秒；单次 GPT 记录为 9.1 秒、195 tokens。这些只是该次输入与运行条件的实测，不能推算全片、实时帧率或后续 API 开销。当前默认只采样起始 8 秒、每秒一帧；保存原尺寸不代表模型处理了原片全部细节，standard 推理尺度为 640，distant 为 1280 并增加人员模型。

## 已知问题与取舍

- 默认作业视频有重复人员、帽及背心框；遮挡、截断和小目标仍有漏检。V13 的 7 秒帧出现四个帽框对应三顶物理帽，框数不能当人数。
- 轨道素材人帽过小，阈值降至 0.20 增加树叶、栏杆等误检，仍未稳定补出帽，因此只撤下领导菜单入口，原视频必须保留。近景候选在默认作业帧也会漏掉整人，不能统一替换全部素材的模型。
- SiteWatch 的 25 类包含车辆、机械、人员和防护装备，并非 25 项安全业务。NO-* 仅为模型待复核类别，装备未检出不能直接变成违规；零检出也不能写成安全。
- 当前是照片与视频采样复核，没有连续事件、人员去重或摄像头监控验收。公开实拍不是水电一局现场，也不是权威违规标签。保留这些边界，同时集中展示清晰、能解释的装备识别结果。
- “人工复核”当前指人工查看检测与第二意见、对照和导出，没有人工结论录入、整改派发或风险事件闭环。视频导出是采样帧 PNG/JSON，不是连续带框 MP4。素材、模型与检测参数切换会清除旧检测显示；修改 GPT 本机配置不会主动隐藏已有区域意见，已有意见以该次实际模型来源为准。

## 按优先级推进

下列工作量是单人净开发粗估，包含相应自测，不是排期承诺；资源恢复、人工标注、用户反馈和训练运行等待另计。按任务顺序检查收益，前一项达标即可停止扩展。

| 优先级与任务 | 具体产物、修改范围及复用 | 前置依赖 | 粗估 |
| --- | --- | --- | --- |
| P0-1 固定演示清单 | 在现有 `demo-media.json` 基础上冻结默认、备用、复核对照及讲解顺序；为每项登记 SHA、模型/尺度/阈值、采样时刻、预期可见目标和已知缺陷。新增小份检查表，不再随机换素材。 | 双方确认展示顺序与关键目标 | 0.5 人日 |
| P0-2 实测配置 | 复用 `probe_hd_models.py`、`check_video_profiles.py` 的逐帧输出方式；只比较现有两模型及有限参数，每条素材独立选择。必要时为 `app/cv_pipeline/detection.py` 增加显式 NMS IoU 参数，同步证据 settings 与缓存签名。 | P0-1；先人工标定检查帧 | 0.5–1.5 人日 |
| P0-3 报告能交接 | 复用 `review_evidence.py` 的 JSON/ZIP，补一页可读摘要：素材来源、分析范围、配置、重点框/裁图、原始判断、GPT 复核状态、附件索引。补充历史意见及其请求配置快照提示；无 API 或失败时显示尚未复核，完整原始输出仍可追溯。 | P0-1；沿用头部复核接口 | 0.5–1 人日 |
| P0-4 固定流程回归 | 复用 `verify.py`、浏览器验证及现有区域边界检查，覆盖素材/模型/画质切换、失败恢复和下载；大证据留本机，只提交脱敏摘要。 | P0-2、P0-3 | 0.5 人日 |
| P1-1 聚焦剩余缺陷 | 只处理检查表里影响讲解的重复框、漏检和遮挡提示；配置有效就固化，不加入缺失装备推断。若需新增展示层筛选，明确区分显示与真实检测，保存筛选理由与原结果。 | P0 对照仍有明确阻塞 | 0.5–1.5 人日 |
| P1-2 可选样例微调 | 只有有限调参无效且缺陷值得修复，才进入下述小规模训练；复用 Ultralytics 数据格式、训练器和验证器，不自写训练框架。 | 标注、许可、隔离环境、资源试跑均具备 | 准备与集成 2–4 人日；训练时间待测 |
| P2 拟议扩展 | GPT 全帧/多区域、事件聚合/跟踪、RTSP、烟火/高处/吊装等，分别形成用途、输入输出、开源复用、成本和验收小方案。 | 先取得新范围确认 | 确认后估算 |

适配仍留在 `sitewatch/app`，上游原件不直接改；改动后更新 `sitewatch/patches/local-review.patch` 并通过来源重建核验。模型登记复用 [model-candidates.json](../sitewatch/model-candidates.json)，不另造模型管理、库存或通用告警引擎。

若领导需要直接播放带框短片，可另列同业务的轻量候选，先确认必要性，再估算逐帧本地检测、编码耗时与依赖。原片继续无损保留，叠框短片另存为派生副本，标明处理帧率与分析范围；不逐帧调用 GPT。当前尚未实施，也不以此替代 P0 已有帧证据交付。

## 对原会议需求的后续承接

原会议安全监测需求与当前 PPE 演示分别追踪，出处及范围澄清见项目任务书。PPE 是后续用户授权优先的视觉演示，不能据此宣称原会议设备业务已实现。

| 原需求 | 当前状态与进入试点的必要条件 |
| --- | --- |
| 真实设备采集、自动上传，减少人工转录 | 未实现；需要设备型号、厂商接口、真实数据样本、字段/时钟约定及测试接入权限。先验证一台设备到既有系统的传输。 |
| 顶拱应力、锚索受力、爆破振动/塌方信息联动，对接业主第三方观测系统 | 未实现；需要真实传感器数据、接口文档、点位与工程人员认可的阈值/联动定义。PPE 模型不能代替工程监测判断。 |
| 地下厂房挖掘机后方 2 米人员/障碍物感应 | 未实现；需要现场视角、遮挡条件、设备运动信息和实距标定，或雷达/测距等传感器。不能把像素阈值当作 2 米，也不能凭目标框证明距离可靠。 |

建议后续只选一条有设备、数据和接口负责人的路线做小试点，先确认输入输出与验收，再确定开源复用和工作量。三项均须实施前取得用户确认，不并入当前 P0 演示优化，不承诺距离精度或上线时点。

## 配置实验与可选训练的做法

先固定 12–20 个检查画面，覆盖默认作业、近景备用和砌筑复核对照；在看新结果前标出可见人员/帽/背心、重叠框与不可判定区域。配置上先保持 640、0.40，单独比较 NMS IoU 0.70/0.50；仅对清晰目标再试 0.50 置信度。确有小目标收益才对少量帧比较 distant，记录额外人员分支及耗时。上限为两轮、合计不超过 40 次逐帧推理，不做全组合搜索；不因“框更少”就认定更好，也不继续普遍降低阈值。

官方 [Predict 文档](https://docs.ultralytics.com/modes/predict/) 说明 `conf`、`iou`、`imgsz` 和 `agnostic_nms` 的用途。本机只读检查已确认安装包为 **8.3.228**，其 `cfg/default.yaml` 的 `iou=0.7`、`agnostic_nms=False`；当前 Detector 显式传入 conf/imgsz，尚未开放 IoU。在线文档随版本变化，不能照抄新默认。保留按类别 NMS，人员与帽等不同类别会自然重叠；调整 IoU 仍须检查相邻真实目标是否被误抑制。原尺寸保存、不增强继续沿用，不能修改图片或手工分数来改善结果。

若配置路线不能解除讲解阻塞，可从已许可固定视频抽取约 30–80 张有差异的帧，人工补齐同一类别体系的标注；不为不可见帽子硬造标签。复用已登记权重做短程适配，训练前冻结目标、样例清单和检查方法。允许训练用过的帧继续演示，但需逐项标记“样例适配”；可留不同时间片检查退化，同源片段也不称独立泛化集。现有 `--include-training` 资源只有可选模型、90 张 RF100 测试图/标签等，**没有完整 train/valid，也没有本轮新训练结果**。

官方 [Train 文档](https://docs.ultralytics.com/modes/train/) 给出数据 YAML、预训练权重及训练入口；本机 8.3.228 源码已有 `train()`、`batch`、`imgsz`、`epochs`、`patience`、`freeze`。这是接口支持核查，未验证本机训练。必须另建训练环境及依赖锁，不向已验收 CPU 演示环境安装 CUDA 包或升级 Torch。先用 batch=1、有限步数试跑，记录峰值显存、实际速度、下载行为与产物；4GB 显存不保证现有权重能训练。失败则缩小试验或停止，借用/租用资源及费用另行确认。新权重通过同一检查表后才登记 SHA、类别与许可，保留原权重和一键切回配置。

## 验收、证据与停止条件

建议 O1 为 P0 演示闭环，O2 为配置改善，O3 为条件成立才做的样例微调；均为待双方确认的新里程碑，不替代 V13 已有验收。建议采用以下可量化门槛：

1. **操作可用**：六项素材按清单各完成一次；默认路径连续三次完成识别、选帧、查看和导出。素材、模型或检测参数切换后旧检测残留为 0；原件下载 SHA 匹配率 100%，导出全部采样时间和参数。GPT 历史意见的实际模型与请求时间显示完整，不把本机新配置套在旧意见上。
2. **改善可见**：在冻结检查表上分别计重复框、明确漏检及误检，遮挡无法判断项单列。O2/O3 至少修复一项事先列出的关键缺陷，且清单内其他关键目标新增漏检/误检为 0，否则不替换默认。只报告这些固定画面的计数，不给现场准确率。
3. **成本可控**：本地检测触发外部 API 次数为 0；GPT 维持按点击单个头部复核、一次请求、不自动重试。一次演示默认最多主动点两次，并记录实际模型、tokens、耗时及失败。历史意见带时间和来源，不能冒充本次实时调用。
4. **报告可审**：摘要和 ZIP 的来源、时间、配置、原始检测、复核状态均可对应；模拟与真实 API 证据分开。保存代码/依赖版本、输入和模型 SHA、命令、退出码、对照计数、耗时及必要截图；不保存 Key。摘要进入 `docs/validation/`，视频、权重和大输出不入 Git。

同因连续失败两次或 20 分钟无新增证据，停下记录诊断并换策略。两轮配置没有收益，就保留 V13 推荐和缺陷说明；训练超资源预算、无可见改善或破坏备用素材，放弃替换，回退原权重。GPT 无 Key、超时或失败时仍演示本地检测与导出，明确尚未复核。默认素材不可用时按冻结清单切近景备用；不现场随机下载大模型，不恢复千问，不改成全帧 GPT。新业务在用途、授权、素材、设备与验收未确认前只留方案，不承诺实时性、事件精度或上线日期。
