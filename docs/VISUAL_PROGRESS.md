## 3. 当前模型分别负责什么

### 3.1 两个已接入界面的 PPE 模型

| 模型 | 当前职责 | 类别数 | 当前推荐场景 |
| --- | --- | --- | --- |
| SiteWatch 自定义 YOLOv8m PPE 权重 | 主检测；识别人、防护装备及其他原生目标类别 | 25 | 默认结构施工视频、砌筑复核对照、自动模式的用户上传 |
| Constructelligence v0.3 | 已注册的可选 PPE 模型 | 14 | 两条 4K 近景视频、两张高清照片 |

`model-candidates.json` 还保存 YOLO11n、SafetyVision 等历史对照模型信息；当前运行检测器仅允许上表两者，不代表所有登记模型都已接入页面。远景模式另有 YOLOv8n 人员伴随分支。

SiteWatch 的 **25 是目标标签数**：人员 1、防护相关 7、机械设施 6、车辆 11。没有对应 25 项独立安全业务。当前页面默认重点展示人员与 PPE，其余标签可展开查看。

### 3.2 头部复核与巡查总结的分工

头部复核仍只发送所选未画框裁图，回答 A/B/C/D。巡查总结是另一条显式入口：从已完成检测中选择首、中、末最多 3 个唯一位置，另存最长边不超过 1280 的全帧 PNG 预览，记录原输入与预览尺寸、SHA、实际帧号和时间。总结只发送这些画面的检测参考，不发送作者标题、人工预期答案；没有头部框也能生成。

两条通道均保持 `gpt-6.1-sol`、推理 `max`、单次请求和 `store:false`。头部的默认输出预算为 4096，总结的 `summary_max_output_tokens` 独立为 8192；旧本机配置缺少新字段时从默认值合并，不改写用户文件。预算、真实响应模型、实际 token 与耗时随同次请求记录。

### 3.3 分数和统计的含义

- YOLO 的 `0.52` 等数值是当前检测框的模型分数，不是该工地准确率。
- GPT 第二意见没有校准概率，不把 YOLO 分数复制成 GPT 的“置信度”。
- `NO-*` 框只表示模型候选；“待人工复核框”是跨帧候选框次数，不是去重人数、独立事件或已确认违规数。
- 总结疑点的三个状态是本机人工记录；只有显式保存才更新。`confirmed` 不是模型自动认定法规违规，`dismissed` 也不表示视频全程安全。
- 独立 JSON 留存人工历史，但当前没有任务历史页面、账号认证、派单或生产整改闭环；主页面也未提供 F5 后自动找回先前任务的能力。

## 8. 当前问题与下一步重点

1. **识别仍有重复、漏检和误检**：优先在固定演示素材上评估阈值、同类重叠处理和模型推荐；不为凑高分手改输出。
2. **缺少可直接播放的带框演示成片**：当前只提供采样画面和证据；是否增加独立派生成片见优化计划。
3. **人工记录限于本机演示**：已能保存总结问题的三状态与备注，尚无任务历史页面、账号、派单、跟踪去重、自动告警或生产整改闭环；不承诺 F5 自动恢复任务。
4. **总结仍受采样范围和 API 开销限制**：头部复核只看裁图，总结只看最多 3 个代表全帧预览；小目标、遮挡及未发送时段仍可能遗漏。真实总结已记录一次 incomplete，成功调用也有等待与 token 开销，展示时按需点击，不连续重发。
5. **真实监测仍缺输入条件**：设备协议、工程数据与物理距离依据尚未接入，应从原会议三项需求中选一条试点，不能用像素距离冒充 2 米。

下一步按 [优化计划](VISUAL_OPTIMIZATION_PLAN.md) 的优先级执行：先把已有演示做稳、做清楚，再视缺口决定是否对固定样例微调；现场实时和设备联动另设验收。
